## Постановка задачи
Реализовать поведение NPC-стражника, патрулирующего набор waypoints в 3D-сцене Unity или 2D-проекте на Python/pygame. Стражник должен:
- [ ] Идти от waypoint к waypoint в режиме патруля.
- [ ] При обнаружении игрока (raycast в FOV без препятствий) переходить в режим тревоги (Alert).
- [ ] После 1 секунды в Alert при сохранении видимости — начать преследование (Chase).
- [ ] При попадании игрока в зону атаки (1.5 м) — атаковать.
- [ ] При потере цели на N секунд — переходить в Search и обходить «последнюю известную позицию».
- [ ] Если в Search не нашёл цель за 10 секунд — возвращаться к патрулю.

##  Подготовка сцены (Пример)
Создать сцену с прямоугольной комнатой 20×20 м, расставить 4 препятствия.
Добавить 4 waypoints в виде Empty/Node3D-объектов.
Добавить NPC-стражника (капсула + NavMeshAgent) и игрока (контроллер от первого/третьего лица).
Запечь NavMesh.

## Пример выполнения

**Где это в играх.** Призраки в Pac-Man — классический конечный автомат: погоня, разбегание по углам, бегство после
энерджайзера. Стражи в Metal Gear Solid, Thief и Splinter Cell живут по той же схеме, что и в этой ЛР: патруль → подозрение →
тревога → поиск → возврат. С Halo 2 (2004) в индустрии закрепились Behavior Trees, сегодня они встроены в Unreal Engine.

**Зачем:** FSM проста и предсказуема, пока состояний мало. Когда их становится 15–20, переходы превращаются в «спагетти»,
и BT позволяет собирать поведение из переиспользуемых блоков. В ЛР вы делаете одно поведение двумя способами и сами
видите эту разницу.

Ориентир, как может выглядеть сданная работа. Числа (углы, дистанции, таймеры) подберите под свою сцену.

**Таблица переходов FSM** (в README вместе с диаграммой):

| Из | Условие | В |
|---|---|---|
| Patrol | игрок в FOV (угол ≤ 60°, дистанция ≤ 10 м) и raycast не упирается в препятствие | Alert |
| Alert | видимость держится ≥ 1 с | Chase |
| Alert | видимость пропала раньше 1 с | Patrol |
| Chase | дистанция ≤ 1.5 м | Attack |
| Attack | дистанция > 1.5 м | Chase |
| Chase | цель не видна N = 3 с | Search |
| Search | игрок снова виден | Chase |
| Search | 10 с без обнаружения | Patrol |

**То же поведение в виде Behavior Tree:**

```text
Selector
├── Sequence  [Атака]   CanSeePlayer? → InAttackRange? → Attack
├── Sequence  [Погоня]  CanSeePlayer? → SeenFor(1 s)? → MoveTo(player)
├── Sequence  [Тревога] CanSeePlayer? → LookAt(player)
├── Sequence  [Поиск]   HasLastKnownPos? → Timer(10 s)? → MoveTo(lastKnownPos)
└── Patrol              MoveTo(nextWaypoint)
```

**Лог переходов**, который стоит выводить в консоль и приложить к работе:

```text
[00:12.4] guard Patrol → Alert   player dist=8.2 m angle=24°
[00:13.4] guard Alert  → Chase
[00:15.0] guard Chase  → Attack  dist=1.4 m
[00:17.8] guard Chase  → Search  lost 3.0 s, last pos (4.1, 7.9)
[00:27.8] guard Search → Patrol
```

**Видео** (1–2 мин): один проход, в котором видны все переходы, сначала в режиме FSM, потом в режиме BT.
Удобно включить Gizmos с конусом обзора и подписью текущего состояния над головой стражника.
